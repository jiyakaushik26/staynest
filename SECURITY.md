# Security Policy

## Supported Versions

Security fixes and updates are applied to the active `main` branch of this repository.

## Reporting a Vulnerability

We take the security of StayNest seriously. If you discover or suspect a security vulnerability in this project, please report it responsibly so we can address it as quickly as possible.

### How to Report

Please **do NOT report security vulnerabilities through public GitHub issues, discussions, or pull requests.** Publicly disclosing an unresolved vulnerability exposes all users and deployments to risk.

Instead, please report vulnerabilities privately through one of the following methods:

1. **GitHub Private Vulnerability Reporting (Recommended)**:
   Submit a confidential report via GitHub's [Security Advisories](https://github.com/vikas0799/staynest/security/advisories/new).
2. **Contact Maintainers Privately**:
   If private vulnerability reporting is unavailable, reach out privately to the repository maintainer ([@vikas0799](https://github.com/vikas0799)) on GitHub.

### What Information to Include

To help us investigate, reproduce, and resolve the issue quickly, please include as much detail as possible in your report:

- **Summary**: A clear description of the vulnerability and its potential impact.
- **Vulnerability Type**: The category of issue (e.g., authentication/authorization bypass, injection flaw, sensitive data exposure, cross-site scripting).
- **Steps to Reproduce**: Detailed step-by-step instructions or a minimal proof-of-concept (PoC) demonstrating how to trigger the issue.
- **Affected Components**: Relevant files, routes, or API endpoints (e.g., `client/src/...`, `server/src/routes/...`, auth middleware).
- **Environment**: Relevant details such as Node.js version, browser, or OS.
- **Suggested Fix / Remediation**: Any code recommendations or patches (if available).

### What to Expect

- **Acknowledgment**: A maintainer will acknowledge receipt of your report within 48 to 72 hours.
- **Assessment**: Maintainers will investigate the vulnerability, determine its severity, and keep you informed of progress.
- **Resolution**: Once verified, a security fix will be prepared, tested, and released.
- **Disclosure**: We follow coordinated vulnerability disclosure. We ask that you maintain confidentiality until a fix has been published and users have had an opportunity to update.
